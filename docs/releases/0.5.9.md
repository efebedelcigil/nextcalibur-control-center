# Nextcalibur 0.5.9

A review of 0.5.5 to 0.5.8 commit by commit, a bug hunt of every path that
writes to the firmware, to Windows or to the machine's permissions, and a
new rule: nothing outside the application changes it.

## Nothing outside the application changes it

- **Settings, lighting and the log moved to where only administrators can
  write**: `%ProgramData%\Nextcalibur\<your account's SID>`. Until now they
  were in `%AppData%`, which any program running as you could rewrite - and
  Nextcalibur, which runs as administrator, turned what they said into
  firmware commands. Your settings are carried over once, and the old
  folder removed.
- **Every file there is recorded**: its hash and a last good copy. On every
  start and every five minutes each is compared with the record; one changed
  from outside is not used, the last good copy is put back, and you are told.
- **The application checks itself**: each release carries the SHA-256 of its
  files. At start and every hour the installed copy compares itself with the
  list, checks that only administrators can write to its folder (and takes
  back any other write permission it finds), and checks that the .NET
  libraries it runs on are signed by Microsoft. If any of that fails, nothing
  is written to the firmware until it is reinstalled.
- **Dependencies are checked before use**: NVIDIA's `nvml.dll` and PawnIO's
  driver are verified through Windows' driver catalog before either is
  loaded; one that fails is not used.

## Fixed

- **The overheat warning under load.** Since 0.5.5, a game or any heavy load
  (a compile counted) made the warning read the processor alone, never the
  graphics card, and hold every warning back until the load ended. It now
  keeps watching both at a lower rate, and waits only while a game has the
  screen.
- **The installer.** Its uninstaller was deleted during installation, so the
  entry in *Installed apps* led nowhere; the wizard's *Start with Windows*
  answer and the first-run power-mode repair never reached the application.
  A copy installed by 0.5.7 or 0.5.8 repairs its *Installed apps* entry on
  its first start.
- **The uninstaller** asks again, as it should, about the power plans, the
  Windows repairs and PawnIO, and no longer removes a folder wholesale -
  only Nextcalibur's own files. Installing into a folder that already holds
  other files is refused.
- **The NDU network fix** is restored only from Nextcalibur's own record,
  never guessed - an NDU switched off by something else is left alone.
- **Installing the .NET runtime or PawnIO** no longer freezes the window for
  the length of Microsoft's installer.
- A power plan that could not be created made Nextcalibur switch Windows to
  Balanced every minute; the lighting restored after sleep could raise an
  error box on waking; a maximised window counted as a game when the taskbar
  hides itself; readings stopped for good after Windows restarted its WMI
  service; the read-only banner on an unsupported machine never showed.
- Security: a lighting effect or an NDU start type taken from a file the
  account could edit; an unfinished uninstall that could leave an elevated
  task pointing into a writable folder; an unused code path that wrote a
  task definition to the temporary folder.

## .NET 10

Nextcalibur now runs on .NET 10, the long-term release supported until
November 2028 (.NET 8 leaves support on 10 November 2026). The installer
installs it from Microsoft when missing; an update from 0.5.8 installs it
first if the machine does not have it.

## Corrections to the 0.5.5 notes

The tray-or-window choice for *Start with Windows* is in the Settings page,
not in the installer; and the runtime download is checked against its
SHA-512, not SHA-256.
