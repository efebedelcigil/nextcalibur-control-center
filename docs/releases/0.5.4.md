# Nextcalibur 0.5.4

## Türkçe

The whole application speaks Turkish or English: every page, every
dialogue, the tray menu, the tour's sixty-seven steps, the sentences the
library writes - a switch's summary, a verdict's reasons, the power modes'
descriptions - and the questions the uninstall asks. The first start takes
the language Windows is set to; *Settings › Behaviour › Language* changes
it at once and the choice is remembered. Mode names, brand names and the
product's name stay as they are in both.

The Turkish was written by the project and will be corrected as it is read;
a wrong word is an issue like any other.

## The language row

The corner button of the previous build is gone; the language lives on the
Settings page, first in the Behaviour group, as a two-way switch in the
style of the interval picker.

## Privacy

A *Privacy* button on the Settings page says in four lines what the
application does with data - nothing collected, nothing sent - and opens
the full policy (`docs/PRIVACY.md`, with the table of every request the
application ever makes) on a yes.

## Security

A review of the application as the thing an unelevated program running as
your account would attack - it runs as administrator, from a task, without
a prompt. Seven findings, all closed; `docs/SECURITY.md` has the rules.

- A copy outside Program Files - an earlier version's install in the
  profile, the portable zip - no longer gets the no-prompt tasks: the
  folder above it is yours, and a folder can be swapped from there. Such
  a copy is asked for administrator rights at every start and a banner
  says why; the installer moves it under Program Files for good. Tasks an
  earlier version registered for such a copy are removed at the next start.
- The task is registered through the Task Scheduler's interface, not via
  a file in the temporary folder that anything could rewrite in between.
- A downloaded installer (PawnIO) is verified with `WinVerifyTrust` - the
  signature must cover the file, not merely be present - and the signer
  matched exactly; it is written where only administrators can reach it,
  under a random name, and held open from the check to the end of the run.
  The wizard does the same from `{app}`.
- The uninstall's delayed script lives in the same protected place.
- Windows tools are run by full path; the current directory and `PATH`
  are never searched for programs or libraries.
- Settings, the lighting state and the log are not written through a
  junction or link in the profile; what is read from them is clamped.

## The .NET runtime is now kept current like everything else

Nextcalibur used to carry the .NET runtime inside itself. That made the
download 65 MB, and it made this project the bottleneck for somebody else's
security fixes: when Microsoft patched .NET, the only way that patch could
reach you was a new Nextcalibur. 0.5.3 is still carrying a runtime that was
five days and five security fixes behind on the day it shipped.

So the runtime is a dependency now, like the PawnIO driver:

- The installer puts it there if your machine has none - Microsoft's own
  installer, signature checked, quietly, before anything starts.
- Windows patches it from then on, along with everything else on the
  machine.
- And when Windows has not got to it yet, Nextcalibur offers it: the same
  *Check now* button, the same notification, the same dialogue as its own
  updates, and the same *Install updates automatically* switch. The
  download is checked against Microsoft's published hash and signature.

The installer is 12 MB instead of 70, and updates are a fraction of what
they were.

If a machine ever loses the .NET 8 runtime but has a newer one, Nextcalibur
now runs on that rather than not at all.

## Security, the second pass

The same review, this time by running the attacks rather than reading the
code - on the machine, with an ordinary process playing the attacker.

- **The .NET runtime inside the application is now checked before a release
  goes out.** A self-contained application is the only thing that patches
  its own runtime: nothing on your machine does it. 0.5.3 shipped 8.0.30
  five days after 8.0.31 fixed five security holes, because the build
  machine happened to have the older one. The release now refuses to
  publish a build whose runtime is behind, or whose .NET channel is out of
  support.
- **Any program running as you could stop Nextcalibur from starting.** It
  asks Windows for two names when it starts, and anything can take those
  names first and refuse to share. It now notices and starts anyway.
- **`--clean-up`, the switch the uninstaller uses, could be pulled by
  anything.** It removes shortcuts, the entry in Installed apps and the
  install folder, and it asks nobody. It refuses to run without
  administrator rights now.
- Text from outside - an error from a server, an exception - can no longer
  forge lines in the log.
- The download link in an update answer must be a release asset of the
  repository it claims to come from, over HTTPS.

Tried and held: libraries planted where the application might look for them
(none were loaded), and the log folder replaced with a link to somewhere
else (nothing was written through it).

## Quieter in the background

- **No firmware reads where there are no readings:** Lighting and Settings
  pages stop the two-second controller polling completely.
- **Cheap sensors gate the expensive ones:** While hidden in the tray, the
  processor's own register (via PawnIO) and the card's (via NVML) are consulted
  first — both cost a memory read and no system-management interrupt. As long
  as both chips are comfortably below warning thresholds, the embedded controller
  is not queried at all.
- **Backed off under heat or gaming:** When temperatures exceed thresholds or
  a game has the display, sensor polling slows to two minutes so interrupts do
  not drop frames or add heat to an already hot machine.
- **Measured hidden cost:** After settling in the notification area: 0.03 %
  of one core, ~25 MB working set, ~675 handles.

## Windows' own faults, watched and put right safely

Some Windows components get stuck spinning a whole core indefinitely, heating
the machine while it sits idle. Nextcalibur watches for these, held to strict
proof:

- **Seven rules of proof before anything is touched:** The component must be
  on an allow-list (currently `TextInputHost.exe`), pinned for 15 minutes unbroken,
  driven by a single thread accounting for 90 % or more of its CPU time, with
  virtually no I/O (< 100 ops), page faults (< 1000) or working set movement
  (< 1 MB), while the rest of the machine is quiet, and with no visible window.
- **Safely restarted, or report-only:** When all seven rules pass, the stuck
  component is safely ended (Windows restarts it when needed); if any rule
  fails, Nextcalibur reports what it found and touches nothing. Every decision
  logs the numbers behind all seven rules. Rate limited to at most once per hour.
- **Discrete card awake with nothing to draw:** Detects when the discrete GPU
  sits in P0 or P1 with under 5 % utilisation and power over 10 W without an
  attached display for 10 minutes unbroken. Reports the draw and names the
  processes holding graphics contexts, with a shortcut to Windows Graphics
  Settings (`ms-settings:display-graphics`). It never terminates processes,
  resets drivers, or touches card clocks.
- **Your switch:** Controlled by the *Compensate for known Windows faults*
  toggle on the Settings page.
- **Optional NDU network driver fix:** Nextcalibur can change at most one machine-wide
  Windows registry value (`HKLM\SYSTEM\CurrentControlSet\Services\Ndu\Start = 4`) if you
  explicitly enable it in Settings to stop multi-gigabyte non-paged pool memory leaks.
  Requires a restart. It costs per-app network usage tracking in Task Manager and Windows
  Settings. The original value is recorded before touching it, and uninstalling
  Nextcalibur asks to restore it back to its original value; the temporary backup marker
  in the service key is deleted at uninstall either way.
- **Kill list guards:** Process restarts are restricted to proven faults (`TextInputHost.exe`
  by default; experimental options for `CrossDeviceService.exe` and `Widgets.exe` default to off).
  `CrossDeviceService` stands down whenever `PhoneExperienceHost.exe` is running to protect active
  Phone Link calls and transfers.
- **Memory trimming only under pressure:** Working set trimming for DWM and Explorer runs
  only under genuine memory pressure (< 15 % free physical RAM) or extreme bloat
  (DWM $\ge$ 2.5 GB, Explorer $\ge$ 2.0 GB). If memory returns within 15 minutes of trimming,
  that memory was live and trimming stands down for that process for an hour to prevent thrashing.
  Reclaimed memory is logged in MB every time alongside system free RAM %, and trimming never runs
  during games, presentation mode, or within 2 minutes of session unlock (trimming is permitted
  while locked/idle to safely reclaim unreferenced pages without disturbing anyone).

## Smaller

- The on/off switches say *açık* / *kapalı* in Turkish, and are a little
  wider for it; the effect tiles fit a two-line name.
- The tour's card re-renders in the new language while it is open.
- Multi-paragraph dialogues keep their paragraphs (the exit question had
  lost its second one).
- The dictionaries now load before the window exists, so the uninstall's
  questions and the first-run repair speak the language you chose rather
  than English.
- The unelevated-era "grant sensor access" path - a second copy of the
  application widening a firmware permission - is gone; the application
  runs elevated and takes such a grant back at start.
- Two new tests: every key the code asks for exists in the dictionaries,
  and the English the library writes beside a key is the English in the
  dictionary.
