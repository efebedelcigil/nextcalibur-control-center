# Nextcalibur 0.5.3

## A guided tour

The `?` in the title bar walks through every page and every control - the
close button included - one at a time, sixty-five steps in eight sections,
with a *Skip to …* for the section you came for, and ends at the tray icon
and its menu. The card never covers what it describes.

## A Settings page

Behind the gear in the rail: everything the tray menu could set, in the
window too, the two always in step. New there: *Install updates
automatically* - a step beyond checking, off by default, and never while a
graphics change is waiting for a restart. And a Tools row: Chris Titus
Tech's WinUtil in an administrator PowerShell (asked first), the laptop
maker's driver page, and the project's issues page.

## Installed under Program Files

The wizard is elevated now and installs under Program Files, and accepts
nothing outside it. The reason: Nextcalibur is started as administrator
without a prompt by a scheduled task, so the files it runs from must sit
where only administrators can write - otherwise anything running as your
account could swap the executable. A copy already installed in the profile
(this update, or the plain installer) is protected by the application
itself at its first elevated start: the folder becomes Administrators',
your account reads it and nothing more; the uninstall hands it back. The
uninstall now removes everything of its own without asking - files,
shortcuts, tasks - and asks only about what you may want to keep: the
power plans, the power repair, and each dependency (PawnIO) separately.

## Everything opened for you opens as you

The browser, the log folder, Windows Settings - opened with the desktop's
own rights, not the application's. Only WinUtil is deliberately elevated.

## Twenty-six things found and fixed

A three-pass hunt through the code, the long-run threats first. Among them:
readings that froze after hide-to-tray and back; two dialogues answering
each other with one click; a chain of processes with no end when the task
could not elevate; the uninstall hook that elevated itself and never ran;
a firmware permission an earlier version widened, taken back; settings
written atomically so a dying battery cannot blank them; the colour wheel
writing to the firmware per pixel of a drag; the Display page stalling on
WMI; a task XML that broke on an ampersand in the path; the log named once
at start; `powercfg` spawned for every plan change.

## Cheaper

Detecting the vendor's software cost 3 ms of processor time every four
seconds - most of what the application spent while idle; it costs 0.03 ms
now. The slow tick no longer reads the firmware a second time while the
window is open. Measured from a copy the person started: about 0.1 % of one
core with the window open, 0.05 % in the tray.

## Watched

The NVIDIA driver, at start and once a minute: removed, the Display page
locks, the card's readings read `--` and the banner says so; back, it all
returns.

## Also

The tidy-up before 1.0: one folder for images, a README in `tools/`, the
single-night captures gone. `docs/FAQ.md`, twenty-eight questions. Start
with Windows survives the update from the Run-entry versions. The corner
has *Up to date* / *Update to vX* and *Open log*.
