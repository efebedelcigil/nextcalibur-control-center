# Nextcalibur 0.5.0

The release where the application stops being a monitor with a lighting page
and becomes the replacement it was meant to be. Everything below was measured
on the reference laptop; nothing was inferred.

## Graphics mode, all three

The Display page switches. Hybrid and Discrete are one write to the firmware
mailbox (`0x0203`: 1 and 2) followed by a restart; UMA switches the card off
in Windows and needs no restart. The card comes back on through a scheduled
task registered once, so switching to UMA and back never asks for
administrator again. After a switch the buttons lock for ten seconds with a
countdown while the driver settles - the crash the vendor's own software has
here, avoided.

Before a firmware switch the page says what it costs: the Windows Hello PIN
has to be set up again, and BitLocker - if it is on - will ask for the
recovery key. Nothing is written until that is answered.

## System mode is now the whole mode

A mode was a Windows power plan and an overlay. It is now also the firmware's
fan and thermal profile (`0x0300`: 0 Performance, 1 Gaming, 2 Office), which
the vendor's software has always written and this one did not. The fans now
behave the same way under each mode as they do there.

The mode follows the charger, as it does there: Office on battery, and the
mode you chose back when the charger returns - unless you changed it by hand
in between, in which case it is left alone. Off from the tray menu if you
prefer. The mode also survives a restart: Windows comes up on Balanced, and
the application puts your mode back.

If the vendor's power plans are removed, the mode makes its own on the spot.
Windows' own hidden "High performance" plan is never chosen; power-mode
overlays do not take effect on it.

## Keyboard backlight and Fn+Space

Fn+Space changes the backlight in firmware. Lighting writes used to reset it
to full without meaning to. They carry the key's level now, and the
brightness slider shows what the keyboard actually shows - the level is read
with every thermal sample, so it is right even for presses made before the
application started.

## A machine that is not this one gets nothing to click

The repository is public. On a laptop without the firmware mailbox every page
is locked and the application offers to uninstall itself. On one with a
mailbox that does not answer like this protocol, readings are shown and
nothing that writes is offered. Nothing about the model name is trusted; the
machine is judged by its own answers to reads.

## Living beside, and after, the vendor's software

Installed alongside, the application recommends removing the other one - once,
and it keeps your answer. If the vendor's software is installed later, the
question is new. When it is uninstalled, its uninstaller takes this
application's firmware permission with it and drops Windows to Balanced; the
application notices, asks once for the permission back, and puts the mode
back.

## Install, uninstall, start

Setup carries the .NET runtime; nothing is downloaded during install. The
application starts with Windows from the first install (tray menu to turn
off). Uninstall removes everything it put on the machine, and asks first
about the two things you might want to keep: the power plans, and the
power-overlay repair.

Every dialogue is silent and blocks the window behind it.

## Under the hood

- `RW_GMWMI` and `GMC_WMIEvent` are granted to the signed-in account in one
  elevation, by adding an entry - never by replacing the vendor's.
- The unknown registers were swept under load, on battery, and with every
  vendor setting toggled; what each one is, and is not, is in PROTOCOL.md.
- 88 tests.
